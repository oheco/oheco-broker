# oheco-broker v0.2.0

平台：HarmonyOS/OpenHarmony `ohos-arm64`。本版本新增独立后台启动、幂等启动，并精简安装包。`0.1.0` 的标签、下载地址和产物保持不变。

## 安装

```sh
oo update
oo install oheco-broker
oheco-broker --version
oheco-broker
```

安装不自动启动服务。服务前台运行，重复启动若确认已有可用 broker，输出提示并以 **0** 正常退出；不修改已有 endpoint，不影响任务。真正的启动错误仍返回非零。

## 独立后台启动

- C：`oheco_broker_spawn_detached(...)`。
- .NET：`BrokerProcess.SpawnDetached(...)` / `SpawnDetachedAsync(...)`。
- 创建新 POSIX 会话，stdin 为 `/dev/null`；stdout/stderr 追加到指定普通文件，空路径为 `/dev/null`。
- 启动成功后客户端断开或 broker 正常退出，不会取消该程序。
- 只返回诊断 PID，没有 Wait/Cancel/重连句柄；服务就绪及停止由程序自身接口或用户终端处理。
- 请求发送后回执丢失或超时可能已经启动成功，不自动重试。

独立启动采用 v2 握手。原受管理执行继续使用 v1：连接断开仍取消命令。新旧受管理客户端/服务保持兼容；对 `0.1.0` 请求独立启动明确返回协议不兼容，不降级为受管理执行。

## 单实例启动

使用由规范 HOME 派生的抽象 Unix socket 名称做原子互斥，**仅作为锁，客户端仍走随机回环 TCP**。同一 HOME/网络命名空间中的 `0.2.0` 不再因私有缓存目录不同而启动多个实例；锁在进程退出或崩溃时自动释放。

通过 endpoint + broker 握手确认现有服务，恢复失效记录，不将普通监听端口误认为 broker。保留旧版缓存锁互操作，并识别已经运行的 `0.1.0`。旧版后来在另一缓存目录中启动不受新锁约束，请避免混用旧启动器。升级时请先正常停止正在运行的旧服务，再启动新版本；重复启动不会自动替换旧进程。

## 原生验证

发布前运行 Go 测试/vet、C 和 .NET 源码 SDK 协议及真实执行测试、真实 dotnet build、生命周期测试和最终归档烟测。

生命周期验收覆盖：不同缓存目录重复启动返回 0、8 个并发启动只有一个服务、崩溃后的锁释放与 endpoint 恢复、非 broker 端口与错误 endpoint、真实启动错误非零、独立程序在 SDK 断开和 broker 进程正常退出后仍存活、追加日志/null stdin，以及与正式发布 `0.1.0` 的 C/.NET 受管理协议兼容。

构建日志、原生测试日志及归档烟测日志随 Release 提供；归档 BUILDINFO 记录确切源码提交、工具链和二进制摘要。

## 安全与限制

**没有鉴权或加密。任何能连接端口的本机进程可以终端身份执行命令。仅用于可信本机开发，不以 root 运行，用完关闭。** 独立服务不会随 broker 关闭，调用者必须负责停止它们。

不保证终端应用被关闭/强停、系统回收整组应用进程后的后台存活。PID 仅作诊断，不是客户端的本地子进程句柄。未提供后台任务数据库、进程树隔离、文件同步、PTY 或系统自启动。不同安全域/网络命名空间仍受平台策略限制，原生终端验证不是所有 HAP 场景保证。本版本不修改 Godot。
