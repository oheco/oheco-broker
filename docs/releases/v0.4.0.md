# oheco-broker v0.4.0

目标平台为 HarmonyOS arm64；Linux amd64、arm64 提供经过原生验证的客户端与服务端 Docker 镜像。C SDK 新增自动重连、手动唤醒和有条件的 TCP 连续恢复，Go SDK 与 CLI 使用同一个 C 引擎。

## 连接恢复

- 网络尝试可更换，逻辑 peer、映射句柄和本地监听端口保持。自动尝试耗尽后进入 `paused`，应用可以在同一句柄上非阻塞地请求手动重连；重复请求合并，健康连接保持原传输。
- 异步初次连接入口在首次网络尝试结束前返回句柄，首次离线也能恢复。既有同步入口和 CLI 的初始 ready JSON 保持用法。
- CLI 在恢复、退避和暂停时继续运行，提供可选 `--state-events`，通过 `SIGUSR1` 请求手动恢复。
- 新传输重新建立授权、PAKE、ICE/TURN、QUIC 和 channel proof。连接 UUID、请求 UUID、预先生成的会话 token 和 generation CAS 使丢失响应后的原请求能够安全重放。
- 映射 v2 使用字节偏移、实际 socket 交付 ACK、有限重放缓存和方向 FIN。满足保留条件时，新 QUIC stream 绑定回原目标 socket，继续原 TCP 流，不重复交付已确认字节。UDP 丢弃断线期间的数据，恢复后建立新流。
- 自然会话过期或替换可获取新传输；身份、凭据或逻辑连接撤销为终止错误。手动重试、新登录及删除历史 SID 不能复活已撤销的授权链。

默认最多 8 次自动尝试，或在 60 秒恢复预算耗尽时暂停。首次恢复立即尝试，随后从 1 秒指数退避；加入 0–25% 抖动后，总等待不超过 15 秒。默认 TCP 保留期限为 120 秒，连续稳定 30 秒后重置失败预算，v2 QUIC 空闲检测为 15 秒并主动保活。运行时降低最大间隔会同时收紧已排定的等待和实际调度时间。

手动请求可以开始新一轮尝试，但不会延长旧 TCP 流的保留期限。`connected` 表示认证传输已建立，各旧流随后完成独立 RESUME 握手。回调不持有 SDK 互斥锁；应用应在自己的线程关闭句柄，不能在该句柄的状态回调内销毁它。

API、调用示例及关闭约束见[恢复指南](<../RECONNECT.md>)；完整契约见[控制 API](<../CONTROL-API.md>)、[Peer 协议](<../PEER-PROTOCOL.md>)及[WS 信令](<../WS-SIGNALING.md>)。

## TURN 授权与计量

TURN 的常用转发路径读取内存中的正向授权结果。首次使用或已缓存租约到期时，通过预编译 SQL 获取当前授权快照；后台每 500 毫秒刷新活跃条目。每次使用仍检查原凭据及 broker、session 的最早绝对到期时间，超过 5 秒未刷新的条目拒绝转发。

本服务的租户、broker 和 session 撤销立即清除相应缓存并关闭适用的中继资源；失效代数阻止进行中的旧查询重新发布权限。直接修改数据库的变化由后台异步观察。刷新查询可取消，服务关闭会等待刷新器退出后再关闭数据库。

每日流量配额也使用内存累计值，实际转发立即计数，后台合并数据库累计量与待落盘批次。落盘保持总量，不重复计费；未知、跨日或失效的配额快照拒绝转发。并发已准入报文可能造成小幅超额，这不是应用层事务或计费预留账本。

TURN 每个 socket 的接收、发送缓冲默认请求 256 KiB；内核可以倍增或限制有效值。UDP 仍为尽力交付。

## 兼容性与迁移

REST 路径保持 `/v1`，WS 子协议保持 `ob-signaling-v1`，PAKE suite、信令 envelope、QUIC v1 与 ALPN `ob-peer-v1` 保持原值。映射 v2 的能力和恢复证明位于 PAKE 认证的 ICE JSON 中；对端未声明 v2 时使用 v1，断线时 v1 的旧 TCP 流结束。旧后端 legacy session 路径不承诺保留目标 socket。

SQLite 启动时将 schema 1 管理数据事务迁移到 schema 2。升级前应使用 SQLite 正规备份。旧服务拒绝 schema-2 数据库；回退需恢复升级前备份。原账号、设备 token 摘要和租户版本继续绑定授权；必要的撤销记录保留以阻止错误重建。撤销记录不占租户活跃配额，但占全局 10,000 条连接记录上限。

## 原生验证

最终功能源码在 HarmonyOS arm64 和 [Linux amd64、arm64 原生 CI](https://github.com/oheco/oheco-broker/actions/runs/37222676784)完成验证。Linux 检查同时覆盖客户端、服务端镜像、TLS、非 root 权限、SQLite schema 2 和两种 Compose 部署模式。

HarmonyOS 普通构建关闭开发诊断宏，完成以下验收：

- 完整 Go 回归与静态检查；授权差异、缓存和配额测试覆盖数据库连接占用、并发首次读取、撤销竞态、过期边界、取消刷新及落盘一致性。
- 实际 C API、WS/WSS、PAKE、TCP/UDP、allowlist、100 秒健康空闲、65,507 字节 UDP、实际流量计量及纯 WS 租约更新。
- CLI 的 1 MiB TCP 回显和 FIN 在原 20 秒检查范围内通过，最大 UDP 报文通过。
- 4 MiB 双向 TCP 续传的 128 个校验帧完整交付：直连 4.207 秒，强制 TURN 5.615 秒。原强制 TURN 验收期限为 150 秒，数据量、原 FD、目标 socket、映射端口及半关闭断言保持。
- 自动预算耗尽、16 个并发手动请求合并、125 条准入 TCP 流恢复、旧流宽限到期、默认检测下 19 秒健康空闲、显式撤销不可复活、首次离线及首次 UDP 黑洞恢复、关闭中断退避。
- 正式安装的 0.3.0 CLI 双向 v1 互通，以及 C 协议和 .NET 10.0.401 的程序集、直接包含源码两种消费方式。

测试使用隔离进程和 fixture，结束后清理自身资源。上述结果不代表任意公网 NAT 或所有设备、系统版本的连通率保证。

## SDK 与安装

运行包的 `sdk/` 包含 C、Go、.NET SDK 的完整源码、固定依赖、许可证及离线构建辅助脚本。另提供独立 `oheco-broker-0.4.0-sdk-source.tar.gz`，内容与运行包中的 SDK 来源一致。运行包为 `oheco-broker-0.4.0-ohos-arm64.tar.gz`；实际源码提交、构建工具链和内容清单见包内 `BUILDINFO.txt` 与 `SHA256SUMS`，下载摘要以 Release 校验文件为准。

正式索引更新后的安装命令：

```sh
oo update
oo install oheco-broker
oheco-broker --version
oheco-broker --help
oheco-broker-server --help
```

透明 TCP 恢复要求双方支持 v2、原授权有效、两个原逻辑上下文和目标 socket 存活，并在原流期限内完成恢复。进程或上下文丢失、目标关闭、撤销、期限耗尽会结束旧流；恢复映射后，应用可以显式建立新流。socket 交付 ACK 不是应用层持久化确认。每流发送和接收缓存各最多 64 KiB，映射层跟踪预算为每 peer 16 MiB；默认 128 流是数量上限，实际准入受字节预算约束，本次验收为 125 条。

TURN 当前使用 UDP/IPv4。映射默认监听 loopback，目标 allowlist 默认拒绝全部。0.1.0、0.2.0、0.3.0 的发行文件及下载地址保持不可变。
