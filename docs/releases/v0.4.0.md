# oheco-broker v0.4.0

目标平台：HarmonyOS arm64。0.4.0 为 C SDK 增加自动重连、手动唤醒和有条件的 TCP 连续恢复；Go SDK 与 CLI 使用同一个 C 引擎。恢复过程中保留逻辑 peer、映射句柄、本地监听端口，以及符合保留期限的 v2 TCP socket。

**发行状态：待完成最终验收。** 已取得下述开发构建与原生运行证据；Linux／Docker 最终验证、正式构建签名与打包、归档迁移、发布和正式索引安装验收尚待完成。本说明不表示 v0.4.0 已发布或可从正式索引安装，最终产物摘要与安装证据由发行流程补齐。

## 新行为

- 可配置自动尝试次数、退避、恢复预算、传输检测、TCP 保留期限及稳定连接后的预算重置。预算耗尽进入 `paused`，句柄和监听端口继续存在。手动重连请求非阻塞、会合并，自动恢复禁用时仍可唤醒；健康连接不会因请求而重建。
- 新增异步初次连接入口，首次网络失败也能在同一 SDK 句柄上恢复。既有同步入口和 CLI 初始 ready JSON 保持其用法。CLI 在恢复、退避和暂停时继续运行，提供可选 `--state-events`，并通过 `SIGUSR1` 请求手动恢复。
- 后端为逻辑连接分配可恢复的授权链：调用方先生成 connection UUID，每次尝试使用 request UUID、64 字符的小写十六进制会话 token 和 generation CAS。丢失响应后重放相同请求取得相同授权；不会因重试额外发放一次会话。新的传输必须重新通过账号／设备／租户授权、PAKE、ICE/TURN、QUIC 和 channel proof。
- 映射 v2 使用字节偏移、实际 socket 交付 ACK、保留重放缓冲及方向 FIN，在传输恢复后将新 QUIC stream 绑定回原目标 socket。不会为旧业务流另连一次目标或重复写入已确认字节。UDP 丢弃断线期间的数据，恢复后只建立新流，不进行可靠重放。
- 自然会话过期与会话替换有明确的 typed reason。`session_expired` / `session_replaced` 可以退役当前尝试并重新申请授权；`connection_revoked` / `credential_revoked` 为终止错误。授权撤销不能被手动重试、新登录或已删除 SID 掩盖。

默认策略为最多 8 次自动尝试、60 秒恢复预算、首次恢复立即尝试、随后 1–15 秒指数退避及 0–25% 抖动、120 秒 TCP 保留期限、30 秒稳定重置；v2 QUIC 默认 15 秒空闲检测并在两端主动保活。手动操作可开始新一轮尝试，**不能延长尚未恢复 TCP 流的原始保留期限**。关闭或撤销是最终操作。

server 的恢复状态反映其控制连接。`connected` peer 表示新的认证传输已建立；各旧 TCP 流还要完成独立 RESUME 握手，不能用一个控制状态快照代替业务流的验收。

API、调用示例和回调关闭约束见[恢复指南](<../RECONNECT.md>)；完整契约见[控制 API](<../CONTROL-API.md>)、[Peer 协议](<../PEER-PROTOCOL.md>)和[WS 信令](<../WS-SIGNALING.md>)。

## 兼容性与数据迁移

REST 路径仍为 `/v1`，WS 子协议仍为 `ob-signaling-v1`，PAKE suite、信令 envelope、QUIC v1 与 ALPN `ob-peer-v1` 保持原值。新增 `mapping_version:2` 和 `resume_proof` 位于 PAKE 认证的 ICE JSON 中。对端未声明映射 v2 时选择 v1；v1 TCP 仍为 OPEN/ACK 后的原始字节流，断线时旧 TCP 流结束。旧后端的 legacy session 路径不承诺保留目标 socket。

SQLite 启动时将 schema 1 的既有管理数据事务迁移为 schema 2，增加逻辑连接与 SID 历史。迁移前需使用 SQLite 正规备份。旧 schema-1 服务会拒绝 schema-2 数据库；回退需恢复升级前备份，不能只改版本字段。原始账号／设备 token 和租户版本保持授权绑定；撤销 tombstone 在原身份仍有效时保留，以阻止丢失初始响应后的错误重建。撤销记录不占租户活跃连接配额，但占独立的全局 10000 条连接存储上限。

已在 HarmonyOS 使用正式安装的 0.3.0 CLI 与新 0.4.0 端点做双向实际互通：每种角色配置完成约 4 MiB 双向 TCP、两条流的 FIN，以及包含 65,507 字节报文的 UDP 校验。旧调用方使用 legacy session 时，新 broker 省略恢复 proof，并回退到 v1 字节流。此前一次旧调用方后续 UDP 建连超时的原因未确定；相同产物随后两次完整验收通过，原失败记录已保留。

- 直连原生用例覆盖 4MiB 级双向校验传输、自动恢复预算耗尽后 16 个并发手动请求合并、同一 TCP socket 上继续传输、方向 FIN／半关闭、断线期间 UDP 丢弃及恢复后新 64KiB UDP、首次离线与首次 UDP 故障恢复、显式撤销不可复活、关闭有界。标准非 trace 库另外通过默认 15 秒检测下的 19 秒健康空闲，以及 5 秒流保留期不被多次手动请求延长的检查。FORCE 中继聚焦验收同样通过全部 128 个帧及恢复／手动／UDP／FIN 检查，从首次故障至 8MiB 下行校验完成耗时 98.324 秒；此前 70 秒测试限时未容纳持续推进的中继传输，现使用 150 秒有界限时，数据量与 socket 身份检查保持原值。包含这些额外用例的标准非 trace 库全矩阵复验记录 656 通过：直连完成耗时 4.326 秒，FORCE 中继 86.990 秒；125 流、宽限、默认空闲检测、授权撤销与初次离线用例均通过。标准库 SHA-256 为 `849fdddc5b564e5c440ddf659cafb6ac770612db9fca6bee6710dfca285b0cf8`。真实 CLI 用例记录 608 也通过：后端退出、自动预算耗尽，重启后向双方发送 `SIGUSR1`，同一应用 FD 与目标 socket 恢复转发。
- Go 回归已通过，记录用时 48.058 秒。额外的原生 cgo 丢失响应／过期会话回归记录 590 通过：已提交但丢失响应的请求按原值重放，typed 410 保留已知 generation，随后用新 request/token 申请下一代；同一句柄保持可恢复状态，不被错误终止。

## 限制与发行门槛

透明 TCP 恢复要求双方支持 v2、后端支持 managed connection、原授权仍有效、两端保留同一个逻辑上下文和目标 socket，并在原始流期限内完成恢复。进程重启、socket 丢失、目标主动关闭、原身份撤销或保留期耗尽都会结束旧 TCP 流；不会把旧流转接到新目标。socket 交付 ACK 也不是应用层持久化或事务确认。

每条 TCP 流的发送重放和接收缓冲各有 64KiB 上限；映射跟踪内存合计不超过每 peer 16MiB，并在同一预算内预留恢复控制空间。默认 128 流设置是数量上限，实际 TCP 准入数还受字节预算和解析工作约束；本阶段实际验收为 125 条。依赖内部内存另有边界，这不是整进程内存恒定值承诺。

UDP 仍为尽力交付。TURN 当前使用 UDP/IPv4；没有 TUN、所有 NAT 的连通率保证或跨进程 TCP 续传保证。账号管理、服务端和 TURN 不接收 peer 密码；映射默认监听 loopback、目标 allowlist 默认拒绝全部。旧 `shell serve` 仍仅适用于可信本机开发，不应作为无鉴权远程目标。

发布前还需完成 Linux／Docker 最终检查、正式客户端／服务端与 C／Go／.NET 源码 SDK 打包、最终签名与校验值、归档解压迁移和正式发布；发布后需核对软件目录部署与正式索引中的安装、版本入口及卸载。尚未完成的项目不会以开发 fixture 结果替代。
