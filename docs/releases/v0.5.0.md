# oheco-broker v0.5.0

账户凭据可自动刷新，长时间运行的 `tenant serve`、`tenant connect` 和 C/Go SDK 进程能持续保持账户授权。刷新沿用同一个登录会话、peer、监听端口、TCP socket 与 TURN allocation；不会增加逻辑连接代数或重新注册 broker。

## 刷新与撤销

默认 access token 有效期为24小时，客户端提前10分钟并加入小幅抖动刷新；refresh token 闲置30天过期，成功刷新延长其闲置期限。绝对登录寿命默认不设上限，可通过 `--auth-absolute-ttl` 配置。旧 access 的新请求准入最多重叠2分钟，且不越过原到期时间。

服务端保存随机256位凭据的 SHA-256 摘要。客户端生成下一组秘密与请求 UUID，在发送前持久化；服务器事务提交后只返回登录会话 ID、代数及期限。回包丢失时重放同一请求，恢复原始提交结果；原 access 已过期而 refresh 仍有效时先确认该结果，再完成新轮转。冲突不会撤销整个登录会话。

退出、修改账户身份或密码、禁用租户及显式撤销仍会停止相应授权。例行刷新不重新发放连接权限，也不能恢复已撤销的连接 ID。新登录关联的 device token 通过有效 heartbeat 原地续期；过期 device 无法续期，显式 offline/token rotation 继续撤销旧授权。

## CLI 与 SDK 迁移

升级旧配置后执行一次：

```sh
oheco-broker --api https://example.org:3478 tenant login
```

同一账户/API 的旧配置可在这次显式登录中使用已保存的密码。新配置采用 version2，保存 refresh 凭据且不保存账户密码；以后刷新无需再次输入密码。新注册需通过交互或 `--password-stdin` 设置账户密码。账户密码与 peer 密码保持不同用途。

刷新使用原配置的持久 `.lock` 与独立 `.refresh-pending`：先 fsync 候选，再发请求；先原子保存并 fsync 已确认配置，再清除 pending。多个进程共享同一个私有配置，可采用已提交的新代数；新的 API、账户或登录会话不会被旧进程静默采用。`tenant refresh` 可手动诊断，仅打印会话 ID、代数和期限。

旧版严格 CLI 不能读取 version2；混用时选择独立 `--config`，或用 `--legacy-auth` 注册／登录生成旧配置。旧的静态 token 接口与 C 构造器保留原行为。

C SDK 新增 `ob_auth.h`、不透明 manager、带大小/版本字段的新 options 和 `ob_api_client_create_with_auth`，旧 `ob_api_options` 布局保持。Go 使用 `remote.NewWithAuth`，通过 `AuthStorage` 回调提供持久化，或选择内存模式。SDK 使用独立计时器、每次请求的不可变 bearer 副本和单个并发刷新事务；关闭时中断并等待 worker，之后才释放存储回调。任意修改 RPC 不会因401而盲目重发，只有既有 CAS 请求等具有自身幂等协议的操作可重试。完整契约见[账户刷新](<../AUTH-REFRESH.md>)。

## 数据库与部署

SQLite schema1/2 在启动时事务迁移到 schema3，保留旧账户、token 摘要、设备及管理数据。新增 `auth_sessions` 和 nullable 登录会话关联，使 connections、普通 sessions、WSS、TURN 与清理都验证同一个稳定授权。

升级前使用 SQLite 正规备份并保留原镜像 digest。旧服务拒绝 schema3；回退需要恢复升级前的数据库备份。不能只修改版本字段或用旧服务直接打开新数据库。

服务端与嵌入式 `server serve` 提供 `--account-token-ttl`、`--auth-refresh-ttl`、`--auth-absolute-ttl`、`--auth-access-overlap`。Linux镜像入口、HTTPS/WSS证书验证、STUN/TURN端口和非root部署方式见[Docker说明](<../DOCKER.md>)。

## 已完成的原生验收

HarmonyOS arm64 的签名 C 客户端完成无 Go runtime 的独立 SDK 验收：空闲自动轮转至 generation3、80次并发账户请求，以及存储回调配对和退出等待。签名 Go SDK 的20个认证与生命周期测试函数、静态检查通过；新增回归证明旧本地 refresh 期限已过、服务器已提交的授权仍存活时，可恢复原回执并取得有效凭据。

隔离 SQLite/Pion 服务上的刷新验收包括：

- TCP/UDP 强制 relay 同时传输32秒，凭据多次轮转，原 TCP 源／目标 socket、所有原生 socket FD/inode、监听端口、逻辑连接 ID 与代数保持；目标只接收一次 TCP 连接，并产生实际 TURN 字节。
- 单独空闲32秒超过测试 refresh 闲置期限，在零账户 HTTP 请求情况下持续自动刷新。
- 六个进程共享配置只提交一次刷新；过期 access 在有效 refresh 下恢复。
- 已提交刷新回包丢失、提交后进程被杀及候选 access 过期后恢复原事务再新轮转。
- 不安全 pending symlink 在 RPC 前拒绝；撤销停止原映射且不自动使用密码登录。
- 服务端物理 schema2 迁移、重启后的持久回执、旧接口、会话限额、长请求准入、同一 TURN allocation/WSS 的三次轮转、原地 device 续期及显式撤销不可复活。
- 一个登录会话退出发生在另一个会话的 TURN SQL 查询和缓存发布之间时，同租户／跨租户的原 allocation 继续双向转发；匹配的失效标记重新检查当前授权，已撤销权限继续拒绝。

验收使用独立进程、配置、数据库与本机 fixture，结束后清理自身资源。上述结果限定于已验证的 HarmonyOS 环境；TCP 网络恢复仍要求两端原进程、授权和目标 socket 保持存活并满足恢复宽限。

## 发行与安装

运行包为 `oheco-broker-0.5.0-ohos-arm64.tar.gz`，含签名 CLI、独立服务端、必要 C++ runtime 与 C/Go/.NET 完整源码 SDK。另有 `oheco-broker-0.5.0-sdk-source.tar.gz`，SDK 由使用者从固定源码离线构建。下载摘要、工具链与源码提交见发行校验文件和包内 `BUILDINFO.txt`、`SHA256SUMS`。

```sh
oo update
oo install oheco-broker
oheco-broker --version
oheco-broker-server --version
```
