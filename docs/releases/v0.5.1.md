# oheco-broker v0.5.1

`tenant serve` 在控制连接的一轮重试耗尽后自动开始后续恢复轮次。此前进程可以一直停在 `paused`：账户凭据仍正常刷新，但心跳停止、broker 离线，网络恢复后仍需 `SIGUSR1` 或重启。

## 持续恢复

每轮仍使用原生引擎的默认上限：最多 8 次尝试、60 秒预算。进入 `paused` 后，CLI 等待 30 秒，再通过同一个 server 句柄请求下一轮；持续进行直到恢复、用户停止或终止授权错误。恢复不重新登录、不旋转设备 token、不重建 server 句柄。

`SIGUSR1` 可以提前唤醒等待，与已经接受的自动唤醒合并。`SIGINT` 和 `SIGTERM` 可立即取消等待。账户或设备授权撤销仍结束进程，不会被下一轮自动恢复绕过。

暂停和恢复提示默认输出到 stderr，每次状态变化一次。stdout 默认保持初次 `broker_ready` JSON；启用 `--state-events` 后，自动 `reconnect_requested` 事件增加 `automatic: true` 字段，手动事件格式保持兼容。

`tenant connect` 和 C/Go SDK 保留既有的有界自动重试及手动暂停恢复语义。TCP 流的默认 120 秒恢复期限独立计时，重复唤醒 server 不延长该期限，已经关闭的旧 socket 不能复活。服务端 API、数据库 schema 和账户刷新协议沿用 0.5.0。

## 构建与使用

HarmonyOS 构建助手 `sdk/c/build/native-toolchain.py` 在私有临时目录中隔离处理已有输入签名：链接时丢弃 SDK CRT 对象的旧签名段，最终使用 PATH 中的 `binary-sign-tool` 签名。显式再次签名采用输入副本，不修改已安装 SDK、编译器或签名配置。Go 自动签名与脚本签名可组合使用；Linux 构建保持原工具调用。

```sh
python3 -B sdk/c/build/native-toolchain.py -- sh scripts/build.sh
```

运行包提供签名 CLI、独立服务端、必要运行库与完整源码 SDK。更新后需要重新启动既有 `tenant serve` 进程一次，使其加载新程序；账户配置和手机端无需为此补丁迁移。

```sh
oo update
oo install oheco-broker
oheco-broker --version
```

回归入口为 `tests/cli_serve_recovery.py`，已接入本机远程验收和 Linux Docker 构建。它使用独立配置、数据库、网络故障 gate 和进程，覆盖真实重试预算耗尽后的自动恢复、账户刷新、设备凭据保持、默认输出兼容、新 TCP 映射，以及撤销和取消。真实受信 HTTPS/WSS 控制源通过 `tests/public_control_smoke.py` 独立验证自动恢复，使用代理及签名测试 socket 转发层，不修改已有账号配置；该公网冒烟不扩大为公网 direct/TURN 数据面覆盖。详细执行记录见 `docs/LOCAL-VALIDATION.md` 及发行验证附件。
